# 大型资源的 OSS 管理与分发

对象存储（OSS）适合集中管理设计原图、纹理源文件、音视频和大型关卡素材。先决定**谁在什么阶段读文件**，再选择上传平台和分发方式。

| 使用场景 | 推荐组合 | 交付边界 |
| --- | --- | --- |
| 小工具和游戏的原始素材 | **团队授权的 OSS 上传平台 + 构建期素材清单 + 转码压缩** | 设计或构建人员从 OSS 取指定版本，导出实际需要的白名单文件，最终页面使用包内路径 |
| 小红书小工具的非首屏资源 | **完整 ZIP + 根目录 `assets/` + 平台静态资源优化 + 按需加载** | 平台在启用范围内外移合规资源，容器按原路径取回。入口和离线核心依赖留主包 |
| 明确允许联网的其他 H5 或游戏容器 | **OSS 源站 + CDN + 版本化资源清单 + 分阶段加载** | 运行时只使用平台许可的域名、接口和资源类型，主包保留离线核心体验 |

小红书小工具仍按 [平台 §2.6–2.7](https://miniapp-sandbox.xiaohongshu.com/minitool/doc#s2-7) 交付。页面不能直接访问外网，签名 OSS URL 或 CDN 域名也不能用作包内引用。平台策略最低客户端为 9.53.3，须在启用范围内新发布，且上传 ZIP 仍包含全部资源。将文件上传到团队 OSS 不会触发平台外移，也不会改变 ZIP 白名单或大小上限。

## 小工具示例：大型关卡美术素材

1. **上传原件。** 把关卡原图和可编辑源文件存到团队授权的 OSS 平台。构建侧清单记录对象路径、版本或内容哈希、授权和使用场景。发布产物只保留运行所需内容。
2. **构建期处理。** 在本地或 CI 下载锁定版本，校验哈希，将图片按实际显示尺寸和画质导出为白名单格式。重复资源去重，模型或媒体先核对容器支持和 ZIP 白名单，再选择可交付的替代素材。
3. **按依赖放置。** 离线首关的必要图放 `critical/level-1.webp` 等主包路径，后续关卡大图可放 `assets/levels/level-2.webp`。两者都进入最终 ZIP。仅在进入第二关时设置图片路径，配 Loading 和失败重试，首关保留可玩。 [平台托管与按需加载示例](./asset-delivery.md) · [启动 Loading](./startup.md)
4. **审计并验收。** 同时看 ZIP、解压大小、解码内存和首关可玩时间。如果完整 ZIP 超出预算，继续缩图、减素材或缩减关卡范围。分别验证冷启动、弱网和离线，区分主包下载与首次取回后续资源的等待。 [资源体积与内存](./asset-size.md) · [指标与真机验收](./metrics.md)

## 允许联网的容器：OSS 配合 CDN 和资源清单

- **上传与权限。** 通过受控上传平台或 CI 上传，按项目隔离对象路径。私有素材使用最小权限。若业务确需客户端直传且容器允许，由服务端签发绑定对象和操作的短期上传 URL，长期密钥保留在服务端。 [阿里云 OSS · 预签名上传](https://www.alibabacloud.com/help/en/oss/user-guide/upload-files-using-presigned-urls)
- **版本与缓存。** 已发布的公开资源用带内容哈希的对象名配合 CDN 长缓存。清单记录版本、路径和依赖，先上传并校验资源，再发布引用它们的清单。保留旧版本供回滚。私有资源的缓存策略需和授权有效期一致，并核对 MIME 类型、允许的来源及目标容器 CSP。 [阿里云 CDN · OSS 加速](https://www.alibabacloud.com/help/en/cdn/use-cases/cdn-acceleration-oss-faq) · [阿里云 OSS · 签名 URL 与缓存](https://www.alibabacloud.com/help/en/oss/why-can-an-expired-signed-object-url-be-used-to-access-object)
- **加载与降级。** 按场景读取清单，限制下载和解码并发。首屏保留本地壳与核心资源，后续关卡或高清素材在用户触发后再取。网络失败按资源独立重试并准备低清或本地回退，分别记录首关可玩和后续资源等待。 [脚本与分阶段启动](./startup.md)

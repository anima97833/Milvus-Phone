# 资源体积与内存

同时量四类成本，按瓶颈选择措施。

| 成本 | 怎么量 | 优化顺序 |
| --- | --- | --- |
| 上传 ZIP 与平台主包 | ZIP 文件字节数；主包单独记录平台实际可见数据 | 删废文件和重复依赖，再压缩并评估外移 |
| 解压后的代码和数据 | 审计目录，总量与大文件排名 | 去掉全量组件、语言包、静态数据和重复 polyfill，按需导入、tree shaking、minify |
| 首屏实际读取与解码 | 冷启动记录已请求的文件、资源就绪和首屏关键路径 | 保留关键资源，只为可见内容设置图片路径；后续资源控制并发 |
| 运行期内存 | 解码尺寸估算，能用工具时采样内存和 GPU 资源 | 按展示尺寸缩图，回收离屏画布、媒体、纹理和不再使用的引用 |

- **图片。** 按布局尺寸和实际需要的 DPR 导出图片，使用白名单内格式。图标先评估 SVG，照片可比较 WebP 与 JPEG 的视觉质量及解码耗时。减少大面积透明和长 GIF，按画面需要压缩。CSS 把原图显示得更小仍可能解码完整原图。RGBA8 单份解码估算为 `宽 × 高 × 4`，2048 × 2048 约 16 MiB，另计拷贝、纹理及 mipmap。
- **字体。** 默认用系统字体。品牌字在授权允许时用 WOFF2 子集，只保留所需字重和字符。用户输入覆盖完整字符集时保留系统字体回退。
- **数据。** 构建期裁字段、预计算索引和摘要，首屏只装载当前视图的小型数据。资源访问遵循 [设备能力](../device-capabilities.md)，小工具方案不使用 `fetch` / `XMLHttpRequest`。不要用运行时解压、大 Base64 或全量同步解析把成本挪到启动阶段。
- **音视频和模型。** 先核对容器允许的来源及后缀。允许的资源再裁时长、帧率和码率，提供占位，用户触发后加载，离开后释放。小工具的音视频及模型后缀边界见 [ZIP 规范](../zip-artifact-spec.md)。

ZIP **最多 10 MiB**，建议不超过 **2 MiB**。文本和 Base64 风险阈值、自动审计与人工兜底见 [性能预算](../performance-budget.md)。不要将 ZIP 压缩率当作启动性能或峰值内存的替代指标。

参考 [MDN · Optimizing canvas](https://developer.mozilla.org/en-US/docs/Web/API/Canvas_API/Tutorial/Optimizing_canvas)。
